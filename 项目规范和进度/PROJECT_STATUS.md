## 当前状态

功能开发处于可使用维护阶段。当前脚本已经从原来的多入口自动删除脚本收敛为“日期范围扫描、预览、多选确认、逐条删除、暂停/继续”的单一工作流。本地静态检查通过；当前 Git 克隆目录已关联维护者的 GitHub 仓库，但没有进行本轮真实 Bilibili 账号操作验证。

## 已完成

- 只保留油猴菜单“选择指定日期之间的动态”和“暂停 / 继续当前任务”。
- 按开始日期和结束日期筛选，日期范围为包含起止日期的闭区间。
- 日期判断使用用户自己转发动态的发布时间。
- 只保留存在有效 `data.orig.id_str` 的转发动态候选，排除原创动态。
- 扫描过程中显示状态窗口、页数、已扫描数量和候选数量。
- 扫描支持通过“停止扫描并预览”按钮提前结束，并预览已经收集的候选。
- 扫描完成、停止和失败都有状态提示。
- 预览显示动态正文、图片、源动态作者、UID、转发日期、判断原因和动态链接。
- 预览默认按转发动态发布时间从新到旧稳定排序。
- 预览支持全选、全不选、手动多选和倒序显示；重排不重新扫描且保留勾选状态。
- 只有用户确认后才发送删除请求。
- 删除任务支持油猴菜单和浮动按钮暂停/继续。
- 删除阶段显示右下角进度面板，实时显示处理进度、成功数、失败数和暂停状态。
- 删除任务结束后显示居中的总结弹窗，失败明细默认收起并支持展开查看。
- 删除成功和暂停/继续不再发送 Windows 通知，避免遮挡右下角进度面板。
- 删除进行中关闭进度面板只隐藏面板；暂停状态下关闭面板会标记任务为已停止、释放暂停等待并显示总结。
- 扫描开始时不再发送重复 Windows 通知；扫描完成、停止和失败仍发送通知。
- 删除任务完成通知显示 3 秒；不承诺该通知进入 Windows 通知中心。
- 删除进度与任务总结的交互方向参考了 ZhuTao3/bilibili-dynamic-del，当前实现已按本项目流程重新设计。
- 删除请求使用转发动态 ID 和 CSRF Cookie，失败时输出接口返回内容。
- 增加接口请求间隔 `1800 ms` 和逐条处理间隔 `700 ms`。
- 增加重复删除保护。
- 已移除原脚本的自动判断菜单、指定用户菜单、设置菜单、自动取关功能及对应存储和请求代码。
- 已移除“按天数删除”的输入方式，避免空输入导致错误匹配全部历史动态。

## 重要技术决策

- “自动判断”在原脚本中指：检查源动态的互动抽奖状态，并删除已开奖的抽奖转发，或源动态已经失效的转发；它不是对所有动态做安全语义判断。该入口已在当前版本移除。
- 当前脚本仍会读取互动抽奖状态，但它只作为候选筛选条件的一部分：未开奖状态 `0` 排除，接口异常跳过；非零且非异常状态可进入日期范围候选。不要把当前流程重新描述为原来的“自动判断”功能。
- 删除时必须使用用户自己的转发动态 ID `data.id_str`；源动态 ID `data.orig.id_str` 只用于识别转发和读取源动态抽奖状态。
- 预览排序依据转发动态时间戳，并使用动态 ID 做稳定次级排序；倒序只改变显示顺序，不改变选择集合或删除对象。
- 扫描阶段的控制按钮是“停止扫描并预览”；“暂停 / 继续当前任务”只对删除阶段生效。不要在状态文档中把扫描停止描述成可暂停后继续扫描。
